You are an expert static analysis assistant. Your task is to identify every line of code that touches a specified target column (`target_column`) in a provided Python script.

### What it Means to "Touch" the Target Column
A line touches the target column if it directly or indirectly:
1. **Ingests / Introduces the Column**: Reads or creates the data containing the column (e.g., `pd.read_csv(...)`, `pd.DataFrame(...)`, loading tables).
2. **References / Reads the Column**: Accesses, evaluates, compares, or filters on the column (e.g., `df['col'] > 0`, `df.loc[..., 'col']`, conditional masks, feature computation).
3. **Writes / Modifies / Transforms the Column**: Mutates, converts types, imputes, or applies functions to the column (e.g., `df['col'] = ...`, `df['col'].astype(...)`, `pd.to_numeric(df['col'])`).
4. **Defines Column Identifiers / Dedicated Mappings**:
   - Lists, tuples, or sets containing the column name (e.g., `cols = ['col1', 'target_col']`).
   - Dedicated lookup tables, dictionaries, or categorization structures specifically defined to map or process values of the target column.
   - Loops iterating over column lists containing the target column.
5. **Propagates / Passes Along the Column**:
   - Copies or re-indexes the DataFrame carrying the column (e.g., `pipeline_df = df.copy()`, `df.set_index(...)`).
   - Subsets that include the target column (e.g., `df[['col1', 'target_col']]`).
   - Grouping, pivoting, or aggregation where the target column is aggregated or passed.
6. **Exports the Column**: Serializes or writes out DataFrames or Series containing the target column (e.g., `df.to_csv(...)`, `df[selected_cols].to_csv(...)`).

### Statement Boundary and Range Rules
- **Complete Statements**: Always capture the full logical statement or expression. If an expression or statement spans multiple lines (e.g., multi-line function calls like `np.where(...)`, chained Pandas calls, multi-line list/dictionary definitions, or `for` loop blocks), include the entire span from the start line to the end line of that statement. Do not isolate only the inner line containing the column string.
- **Merge Adjacent / Overlapping Ranges**: Combine overlapping or contiguous line ranges into a single range `{"start_line": start, "end_line": end}`.
- **1-Based Indexing**: Line numbers are 1-based.
- **Sorting**: Order ranges by `start_line` in ascending order.

### Output Format
Respond ONLY with a valid JSON object matching the following schema:
```json
{
  "sources": [
    { "start_line": int, "end_line": int }
  ]
}
```

### Core Deequ Verification Mapping Rules & Phrasing Conventions
Each assumption must be framed using exact, standardized templates to enable automated mapping to Deequ constraints:

1. **Completeness (`.isComplete`)**:
   - **Target statement**: `"<target_column> must be complete and contain no null or missing values."`
   - **Trigger cues**:
     - Column is used as a join key, `groupby` grouping column, `pivot_table` index/column, or `set_index` key.
     - Column is cast via `pd.to_numeric(..., errors='coerce')` without subsequent fill/filter, or passed to mathematical transformations (e.g., `np.log`, division, square roots) where nulls propagate to corrupted outputs or NaN aggregations.
     - Metadata shows `completeness: 1.0` and the column is essential for row-level transformations or exported reports.

2. **Data Type (`.hasDataType`)**:
   - **Numeric**:
     - **Target statement**: `"<target_column> must have a numeric (integral/fractional) data type."`
     - **Deequ mapping**: `.hasDataType('<target_column>', ConstrainableDataTypes.Numeric)`
     - **Trigger cues**: Mathematical expressions (`+`, `-`, `*`, `/`), math functions (`np.log`, `np.sqrt`, `np.minimum`), numeric comparisons (`<`, `<=`, `>`, `>=`), numeric binning (`pd.cut`), or explicit `pd.to_numeric` conversions. Metadata shows `dataType: Integral` or `dataType: Fractional`.
   - **String**:
     - **Target statement**: `"<target_column> must have a string data type."`
     - **Deequ mapping**: `.hasDataType('<target_column>', ConstrainableDataTypes.String)`
     - **Trigger cues**: String methods, dictionary key lookups (`map(dict)`), categorical/text aggregations, or metadata `dataType: String`.
   - **Boolean**:
     - **Target statement**: `"<target_column> must have a boolean data type."`
     - **Deequ mapping**: `.hasDataType('<target_column>', ConstrainableDataTypes.Boolean)`

3. **Positivity & Non-negativity (`.isPositive`, `.isNonNegative`)**:
   - **Strictly Positive (`> 0`)**:
     - **Target statement**: `"<target_column> values must be strictly positive (greater than 0)."`
     - **Deequ mapping**: `.isPositive('<target_column>')`
     - **Trigger cues**:
       - Column is used inside logarithms (e.g., `np.log(df['target_column'])`, where `<= 0` produces `-inf` or `nan`).
       - Column is a denominator in division or ratio calculations without a zero-fallback.
       - Column is used in strict lower-bound conditions like `s > 0` or binning intervals with `bins = [0, ...]`, `include_lowest=False`.
       - Metrics where zero is invalid in real-world domains (e.g., income, salary, active tenure when division follows).
   - **Non-negative (`>= 0`)**:
     - **Target statement**: `"<target_column> values must be non-negative (greater than or equal to 0)."`
     - **Deequ mapping**: `.isNonNegative('<target_column>')`
     - **Trigger cues**:
       - Physical or business counts, percentages, tenure metrics, or amounts where zero is legitimate (e.g., `YearsSinceLastPromotion`, `PercentSalaryHike`, headcount, gap calculations like `TotalWorkingYears - YearsAtCompany` before `np.sqrt`).

4. **Allowed Value Set / Membership (`.isContainedIn`)**:
   - **Target statement**: `"<target_column> values must be contained in the allowed set: [<val1>, <val2>, ...]."`
   - **Deequ mapping**: `.isContainedIn('<target_column>', Array(<val1>, <val2>, ...))`
   - **Trigger cues**:
     - Lookups through explicit dictionaries (e.g., `dict.keys()`), `pd.CategoricalDtype(categories=[...])`, or discrete filter masks (`.isin([...])`).
     - Look for categories present in `target_column_desc.histogram` when the code relies on closed-world categorical domain mappings.

5. **Value Bounds / Range (`.hasMin`, `.hasMax`)**:
   - **Target statement**: `"<target_column> values must be between <min> and <max>."` (or separate min/max statements).
   - **Trigger cues**: Hard boundaries implied by domain rules (e.g., ratings 1 to 5, percentages 0 to 100, age bins starting at 18).

6. **Uniqueness (`.isUnique`)**:
   - **Target statement**: `"<target_column> values must be unique across all rows."`
   - **Trigger cues**: Target column is an entity identifier (`EmpID`, `EmployeeNumber`), unique key used to index (`set_index(..., drop=False)`), or 1:1 merge key.

---

### Analysis & Derivation Strategy

1. **Identify Multi-Layer Constraints**:
   - Do **not** stop after generating a single assumption. A column typically requires multiple complementary constraints. For example:
     - A monetary feature like `MonthlyIncome` passed to `np.log` requires:
       1. Completeness (`.isComplete`)
       2. Data type (`.hasDataType` Numeric)
       3. Strict positivity (`.isPositive`)
     - An identifier column like `EmpID` requires:
       1. Completeness (`.isComplete`)
       2. Uniqueness (`.isUnique`)
     - A rate or hike column like `PercentSalaryHike` requires:
       1. Completeness (`.isComplete`)

     - `np.log(col)`: Negative values yield `NaN`, zero yields `-inf`. This strictly necessitates `.isPositive`.
     - `df.pivot_table(..., columns=col)` or `df.groupby(col)`: Missing values are dropped or create unintended null buckets, requiring `.isComplete`.
     - `dict.map(col)`: Unmapped values become `NaN`, leading to downstream aggregation corruption. This necessitates `.isContainedIn` and `.isComplete`.

3. **Trace Exact Code Lines (`sources`)**:
   - Anchor each assumption to the specific line numbers that define, enforce, or expose the code to that assumption. You are an expert data quality and data reliability engineer. Your task is to translate a list of assumptions about a dataset's target column into executable PyDeequ verification checks, correctly determining the severity level (`error` vs `warning`) for each check based on downstream code execution risks.

---

### Task Description

Given:
1. `target_column`: The name of the column being validated.
2. `target_column_desc`: Profiling metadata for the target column (data type, completeness, distinct values count, histograms, etc.).
3. `code_snippet`: The downstream Python script (typically using pandas, numpy, etc.) that ingests and processes the dataset.

5. `assumptions`: A numbered list (starting from index 0) of data assumptions regarding the target column, along with source line references in the script.

Generate a JSON object containing the translated PyDeequ constraints in the exact schema:
```json
{
  "constraint_code": [
    {
      "suggestion": "<PyDeequ method chain starting with '.'>",
      "level": "error" | "warning",
      "linked assumptions": [0, 1]
    }
  ]
}
```

---

### Severity Level Guidelines (`error` vs `warning`)

Accurately distinguishing between `error` and `warning` is vital. Test batches containing data issues that crash the script must be flagged with `error`. If an unsafe batch only triggers `warning` checks, the execution failure will not be intercepted.

Carefully trace how `target_column` is used in the `code_snippet`:

#### Set `level = "error"` if invalid data will CRASH the code:
- **Type Incompatibilities**:
  - The column undergoes arithmetic operations (`+`, `-`, `*`, `/`) or relational comparisons (`<`, `>`, `<=`, `>=`) without explicit type conversion or error coercion (e.g., `pd.to_numeric(..., errors='coerce')`). In Python 3 / pandas, comparing or operating on mixed types (e.g., string vs numeric) raises unhandled `TypeError` exceptions.
- **Null / Missing Values**:
  - Nulls propagate into operations that cannot handle `NaN`, such as:
    - Explicit casts to integer (e.g., `.astype(int)`, `int(val)`), which throw `ValueError: Cannot convert non-finite values (NA or inf) to integer`.
    - Key lookups without defaults (e.g., `dict[val]`, `df.loc[val]`).
    - Methods requiring non-null strings (e.g., unhandled `.apply()` functions or string accessors).
- **Domain & Value Boundaries**:
  - Values outside expected boundaries causing mathematical exceptions (e.g., negative values passed to `np.sqrt()`, or zeros passed as denominators in operations not protected by `np.where(...)` or `replace(0, ...)`).
  - Categorical or mapping mismatches: using direct dictionary access `d[x]` or mapping without fallback where unmapped values produce `NaN` that subsequently triggers a downstream crash.

#### Set `level = "warning"` if invalid data degrades quality but DOES NOT CRASH the code:
- Missing or malformed data is handled gracefully (e.g., `pd.to_numeric(..., errors='coerce')` converts invalid types to `NaN`).
- Calculations naturally tolerate `NaN` (e.g., pandas aggregations like `.mean()`, `.sum()`, `.count()` which skip NaNs by default).
- Logic handles nulls safely via `np.where(condition, ..., np.nan)` or `.fillna()`.
- The assumption represents a statistical distribution, business heuristic, or data freshness guideline rather than a structural execution requirement.

---

### Constraint Construction Rules

1. **Syntax**:
   - Each `suggestion` must be a valid PyDeequ check call starting with `.` (e.g., `.isComplete('col')`, `.hasDataType('col', ConstrainableDataTypes.Numeric)`).
   - Use raw string literals (`r"..."`) for regular expressions in `hasPattern`.
   - Match the data types in `isContainedIn`: if the column is integral, pass numeric values or representations matching the PyDeequ/Spark schema.
2. **Data Types**:
   - When using `hasDataType`, only use enum members from `ConstrainableDataTypes`:
     `ConstrainableDataTypes.Null`, `ConstrainableDataTypes.Fractional`, `ConstrainableDataTypes.Integral`, `ConstrainableDataTypes.Boolean`, `ConstrainableDataTypes.String`, `ConstrainableDataTypes.Numeric`.
3. **Linked Assumptions**:
   - Provide a list of integer indices (0-based) referencing the specific assumptions validated by the check.

---

### Available PyDeequ Functions Reference

#### Row-Level Functions:
- `.isComplete(column)`: Validates that a column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness fraction (0.0 to 1.0) matches lambda. Example: `.hasCompleteness('col', lambda x: x >= 0.95)`
- `.areComplete(columns)`: Validates that all columns in a list contain no null values.
- `.haveCompleteness(columns, assertion)`: Validates completeness fraction across a list of columns.
- `.areAnyComplete(columns)`: Validates that at least one column in a list contains no null values.
- `.satisfies(columnCondition, constraintName, assertion=None)`: Validates a SQL WHERE clause condition. Example: `.satisfies('`credits_completed` <= `credits_attempted`', 'completed_le_attempted')`
- `.hasPattern(column, pattern, assertion=None, name=None)`: Validates regex match. Example: `.hasPattern('student_id', r'^id_\d+$')`
- `.containsCreditCardNumber(column, assertion=None)`: Validates credit card number format.
- `.containsEmail(column, assertion=None)`: Validates email format.
- `.containsURL(column, assertion=None)`: Validates URL format.
- `.containsSocialSecurityNumber(column, assertion=None)`: Validates US SSN format.
- `.hasDataType(column, datatype, assertion=None)`: Validates data type using `ConstrainableDataTypes`.
- `.isNonNegative(column, assertion=None)`: Validates column >= 0.
- `.isPositive(column, assertion=None)`: Validates column > 0.
- `.isLessThan(columnA, columnB, assertion=None)`: Validates columnA < columnB.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA <= columnB.
- `.isGreaterThan(columnA, columnB, assertion=None)`: Validates columnA > columnB.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA >= columnB.
- `.isContainedIn(column, allowed_values, assertion=None)`: Validates values belong to an allowed set. Example: `.isContainedIn('dept', ['HR', 'Sales'])`

#### Aggregate-Level Functions:
- `.hasSize(assertion)`: Validates total row count. Example: `.hasSize(lambda x: x >= 1000)`
- `.haveAnyCompleteness(columns, assertion)`: Validates at least one column in a set meets completeness threshold.
- `.isUnique(column)`: Validates that all values in a column are unique.
- `.hasUniqueness(columns, assertion)`: Validates ratio of values occurring exactly once.
- `.hasDistinctness(columns, assertion)`: Validates ratio of distinct values to total rows.
- `.hasUniqueValueRatio(columns, assertion)`: Validates ratio of unique values to distinct values.
- `.hasNumberOfDistinctValues(column, assertion, binningUdf=None, maxBins=1000)`: Validates count of distinct values.
- `.hasMutualInformation(columnA, columnB, assertion)`: Validates mutual information between two columns.
- `.hasApproxQuantile(column, quantile, assertion)`: Validates quantile value. Example: `.hasApproxQuantile('gpa', 0.5, lambda x: x >= 3.0)`
- `.hasMinLength(column, assertion)`: Validates minimum string length.
- `.hasMaxLength(column, assertion)`: Validates maximum string length.
- `.hasMin(column, assertion)`: Validates minimum numeric value.
- `.hasMax(column, assertion)`: Validates maximum numeric value.
- `.hasMean(column, assertion)`: Validates mean of a numeric column.
- `.hasStandardDeviation(column, assertion)`: Validates standard deviation.
- `.hasCorrelation(columnA, columnB, assertion)`: Validates Pearson correlation (-1.0 to 1.0).
