### Core Deequ Verification Mapping Rules & Phrasing Conventions
Each assumption must be framed using exact, standardized templates to enable automated mapping to Deequ constraints:

1. **Completeness (`.isComplete`)**:
   - **Target statement**: `"<target_column> must be complete and contain no null or missing values."`
   - **Trigger cues**:
     - Column is used as a join key, `groupby` grouping column, `pivot_table` index/column, or `set_index` key.
     - Column is cast via `pd.to_numeric(..., errors='coerce')` without subsequent fill/filter, or passed to mathematical transformations (e.g., `np.log`, division, square roots) where nulls propagate to corrupted outputs or NaN aggregations.
     - Metadata shows `completeness: 1.0` and the column is essential for row-level transformations or exported reports.

2. **Data Type (`.hasDataType`)**:
   - **Numeric**:
     - **Target statement**: `"<target_column> must have a numeric (integral/fractional) data type."`
     - **Deequ mapping**: `.hasDataType('<target_column>', ConstrainableDataTypes.Numeric)`
     - **Trigger cues**: Mathematical expressions (`+`, `-`, `*`, `/`), math functions (`np.log`, `np.sqrt`, `np.minimum`), numeric comparisons (`<`, `<=`, `>`, `>=`), numeric binning (`pd.cut`), or explicit `pd.to_numeric` conversions. Metadata shows `dataType: Integral` or `dataType: Fractional`.
   - **String**:
     - **Target statement**: `"<target_column> must have a string data type."`
     - **Deequ mapping**: `.hasDataType('<target_column>', ConstrainableDataTypes.String)`
     - **Trigger cues**: String methods, dictionary key lookups (`map(dict)`), categorical/text aggregations, or metadata `dataType: String`.
   - **Boolean**:
     - **Target statement**: `"<target_column> must have a boolean data type."`
     - **Deequ mapping**: `.hasDataType('<target_column>', ConstrainableDataTypes.Boolean)`

3. **Positivity & Non-negativity (`.isPositive`, `.isNonNegative`)**:
   - **Strictly Positive (`> 0`)**:
     - **Target statement**: `"<target_column> values must be strictly positive (greater than 0)."`
     - **Deequ mapping**: `.isPositive('<target_column>')`
     - **Trigger cues**:
       - Column is used inside logarithms (e.g., `np.log(df['target_column'])`, where `<= 0` produces `-inf` or `nan`).
       - Column is a denominator in division or ratio calculations without a zero-fallback.
       - Column is used in strict lower-bound conditions like `s > 0` or binning intervals with `bins = [0, ...]`, `include_lowest=False`.
       - Metrics where zero is invalid in real-world domains (e.g., income, salary, active tenure when division follows).
   - **Non-negative (`>= 0`)**:
     - **Target statement**: `"<target_column> values must be non-negative (greater than or equal to 0)."`
     - **Deequ mapping**: `.isNonNegative('<target_column>')`
     - **Trigger cues**:
       - Physical or business counts, percentages, tenure metrics, or amounts where zero is legitimate (e.g., `YearsSinceLastPromotion`, `PercentSalaryHike`, headcount, gap calculations like `TotalWorkingYears - YearsAtCompany` before `np.sqrt`).

4. **Allowed Value Set / Membership (`.isContainedIn`)**:
   - **Target statement**: `"<target_column> values must be contained in the allowed set: [<val1>, <val2>, ...]."`
   - **Deequ mapping**: `.isContainedIn('<target_column>', Array(<val1>, <val2>, ...))`
   - **Trigger cues**:
     - Lookups through explicit dictionaries (e.g., `dict.keys()`), `pd.CategoricalDtype(categories=[...])`, or discrete filter masks (`.isin([...])`).
     - Look for categories present in `target_column_desc.histogram` when the code relies on closed-world categorical domain mappings.

5. **Value Bounds / Range (`.hasMin`, `.hasMax`)**:
   - **Target statement**: `"<target_column> values must be between <min> and <max>."` (or separate min/max statements).
   - **Trigger cues**: Hard boundaries implied by domain rules (e.g., ratings 1 to 5, percentages 0 to 100, age bins starting at 18).

6. **Uniqueness (`.isUnique`)**:
   - **Target statement**: `"<target_column> values must be unique across all rows."`
   - **Trigger cues**: Target column is an entity identifier (`EmpID`, `EmployeeNumber`), unique key used to index (`set_index(..., drop=False)`), or 1:1 merge key.

---

### Analysis & Derivation Strategy

1. **Identify Multi-Layer Constraints**:
   - Do **not** stop after generating a single assumption. A column typically requires multiple complementary constraints. For example:
     - A monetary feature like `MonthlyIncome` passed to `np.log` requires:
       1. Completeness (`.isComplete`)
       2. Data type (`.hasDataType` Numeric)
       3. Strict positivity (`.isPositive`)
     - An identifier column like `EmpID` requires:
       1. Completeness (`.isComplete`)
       2. Uniqueness (`.isUnique`)
     - A rate or hike column like `PercentSalaryHike` requires:
       1. Completeness (`.isComplete`)
       2. Data type (`.hasDataType` Numeric)
       3. Non-negativity (`.isNonNegative`)

2. **Audit Code Vulnerabilities**:
   - Check what would cause silent data corruption or runtime crashes:
     - `pd.to_numeric(..., errors='coerce')`: Null values will silently be injected if non-numeric strings appear, contaminating subsequent averages/sums. This is an explicit cue for both `.hasDataType(Numeric)` and `.isComplete`.
     - `np.log(col)`: Negative values yield `NaN`, zero yields `-inf`. This strictly necessitates `.isPositive`.
     - `df.pivot_table(..., columns=col)` or `df.groupby(col)`: Missing values are dropped or create unintended null buckets, requiring `.isComplete`.
     - `dict.map(col)`: Unmapped values become `NaN`, leading to downstream aggregation corruption. This necessitates `.isContainedIn` and `.isComplete`.

3. **Trace Exact Code Lines (`sources`)**:
   - Anchor each assumption to the specific line numbers that define, enforce, or expose the code to that assumption. If an assumption is established across multiple functions or lines (e.g., type casting at line 50 and mathematical operation at line 60), include all relevant disjoint or contiguous line ranges in the `sources` list.

```json
    }

```

### Critical Severity Calibration (`error` vs `warning`)

An automated evaluation framework tests your generated checks against both **safe batches** (clean data conforming to the baseline) and **unsafe batches** (data injected with corruptions that violate assumptions and break downstream processing).

- **Only checks with `level = "error"` can flag unsafe batches.** If an assumption violation is marked as `warning`, the validation suite does not intercept the unsafe batch, leading to 0 errors caught and severely penalizing the quality score (Macro F1).
- Safe batches already conform to valid baseline data. Formulating valid integrity checks as `error` does **not** trigger false alarms on safe batches.
- **Do not assume pandas silently handling `NaN` or invalid types makes a constraint safe to demote to `warning`.** Even if pandas aggregations (e.g., `.mean()`, `.sum()`, `groupby(..., dropna=False)`) technically execute without raising an unhandled exception, corrupting these values invalidates business logic, distorts downstream metrics, propagates unmapped `NaN` values, or triggers downstream crashes.

---

### Severity Level Guidelines

#### Set `level = "error"` for Structural & Integrity Requirements:
Assign `level = "error"` to any check that validates a foundational assumption required for reliable downstream execution:
1. **Completeness (`.isComplete`)**:
   - The column is used in grouping (`groupby`), pivoting (`pivot_table`), categorical conversions (`.astype(pd.CategoricalDtype)`), dictionary mappings (`.map()`), filtering, or arithmetic/relational operations without explicit imputation/fallback handling.
   - The column is a primary entity attribute or key metric.
2. **Data Types (`.hasDataType`)**:
   - The column undergoes arithmetic operations, numeric comparisons (`<`, `<=`, `>`, `>=`), categorical typing, or string methods. Type mismatches (e.g., string injected into an integer tenure column) break operations or crash the script.
3. **Categorical Domains (`.isContainedIn`)**:
   - The column has an enumerated set of allowed values used in dictionary lookups (`dict[val]` or `.map(dict)`), ordered/unordered categorical types (`pd.CategoricalDtype(categories=[...])`), or fixed cohort segmentation. Unexpected categories cause silent mapping drops to `NaN`, missing aggregation buckets, or downstream errors.
4. **Domain Boundaries & Validity (`.isNonNegative`, `.isPositive`, `.satisfies`)**:
   - The column represents physical, logical, or temporal quantities (e.g., age, tenure, years since event, salary, counts) used in conditional readiness flags, ratio denominators, or thresholds. Negative or invalid boundary values violate domain logic and produce invalid analytical states.

#### Set `level = "warning"` ONLY for Soft Heuristics & Statistical Checks:
Reserve `level = "warning"` strictly for non-critical guidelines where a violation indicates slight data drift rather than corrupted or breaking data:
1. **Statistical Distributions**:
   - Checks on distribution parameters: `.hasMean()`, `.hasStandardDeviation()`, `.hasApproxQuantile()`, `.hasCorrelation()`.
2. **Cardinality & Uniqueness Heuristics**:
   - Approximate distinct value counts or uniqueness ratios (`.hasNumberOfDistinctValues()`, `.hasDistinctness()`, `.hasUniqueValueRatio()`) when the column is not a strict unique primary key.
3. **Soft Thresholds**:
   - Fractional completeness checks with relaxed tolerances (e.g., `.hasCompleteness(..., lambda x: x >= 0.90)`).
   - String length boundary heuristics (`.hasMinLength()`, `.hasMaxLength()`) that are informative rather than strict schema requirements.

---

### Constraint Construction Rules

1. **Syntax**:
   - Each `suggestion` must be a valid PyDeequ method chain call starting with `.` (e.g., `.isComplete('col')`, `.hasDataType('col', ConstrainableDataTypes.Numeric)`).
   - Use raw string literals (`r"..."`) for regular expressions in `.hasPattern()`.
   - Match the data types in `.isContainedIn()`: if the column is string-based, provide list of strings; if numeric/integral, provide numbers matching the schema.

3. **Linked Assumptions**:
   - Each constraint must include a list of 0-based integer indices referencing the specific assumptions it validates.

### Available PyDeequ Functions Reference

#### Row-Level Functions:
- `.isComplete(column)`: Validates that a column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness fraction (0.0 to 1.0) matches lambda.
- `.areComplete(columns)`: Validates that all specified columns contain no null values.
- `.haveCompleteness(columns, assertion)`: Validates completeness fraction across a list of columns.
- `.areAnyComplete(columns)`: Validates that at least one column in a list contains no null values.
- `.satisfies(columnCondition, constraintName, assertion=None)`: Validates a SQL WHERE clause condition. Example: `.satisfies('`credits_completed` <= `credits_attempted`', 'completed_le_attempted')`
- `.hasPattern(column, pattern, assertion=None, name=None)`: Validates regex match. Example: `.hasPattern('student_id', r'^id_\d+$')`
- `.containsCreditCardNumber(column, assertion=None)`
- `.containsEmail(column, assertion=None)`
- `.containsURL(column, assertion=None)`
- `.containsSocialSecurityNumber(column, assertion=None)`
- `.hasDataType(column, datatype, assertion=None)`: Validates data type using `ConstrainableDataTypes`.
- `.isNonNegative(column, assertion=None)`: Validates column >= 0.
- `.isPositive(column, assertion=None)`: Validates column > 0.
- `.isLessThan(columnA, columnB, assertion=None)`: Validates columnA < columnB.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA <= columnB.
- `.isGreaterThan(columnA, columnB, assertion=None)`: Validates columnA > columnB.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA >= columnB.
- `.isContainedIn(column, allowed_values, assertion=None)`: Validates values belong to an allowed set. Example: `.isContainedIn('dept', ['HR', 'Sales'])`

#### Aggregate-Level Functions:
- `.hasSize(assertion)`: Validates total row count. Example: `.hasSize(lambda x: x >= 1000)`
- `.isUnique(column)`: Validates that all values in a column are unique.
- `.hasUniqueness(columns, assertion)`: Validates ratio of unique values.
- `.hasDistinctness(columns, assertion)`: Validates ratio of distinct values to total rows.
- `.hasUniqueValueRatio(columns, assertion)`: Validates ratio of unique values to distinct values.
- `.hasNumberOfDistinctValues(column, assertion, binningUdf=None, maxBins=1000)`: Validates count of distinct values.
- `.hasMutualInformation(columnA, columnB, assertion)`: Validates mutual information between two columns.
- `.hasApproxQuantile(column, quantile, assertion)`: Validates quantile value. Example: `.hasApproxQuantile('gpa', 0.5, lambda x: x >= 3.0)`
- `.hasMinLength(column, assertion)`: Validates minimum string length.
- `.hasMaxLength(column, assertion)`: Validates maximum string length.
- `.hasMin(column, assertion)`: Validates minimum numeric value.
- `.hasMax(column, assertion)`: Validates maximum numeric value.
- `.hasMean(column, assertion)`: Validates mean of a numeric column.
- `.hasStandardDeviation(column, assertion)`: Validates standard deviation.
- `.hasCorrelation(columnA, columnB, assertion)`: Validates Pearson correlation (-1.0 to 1.0).
