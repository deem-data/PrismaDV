### Constraint Level Guidelines (`error` vs. `warning`)
- **Mandatory Requirement**: Do NOT emit an output containing only `"warning"` constraints. If all constraints are warnings, a bad or corrupt batch will never be rejected. **At least one constraint must be set to `level: "error"`** to ensure pipeline integrity and prevent corrupted data from propagating.
- **Assign `"error"`** to:
  - Critical foundational constraints (e.g., column completeness/presence when expected, fundamental format/type validation, or essential value constraints).
  - Checks where failing the condition breaks pipeline execution, causes unhandled exceptions in downstream processing, or fundamentally corrupts downstream consumers.
- **Assign `"warning"`** to:
  - Soft data quality thresholds (e.g., non-fatal distribution drift, minor completeness drop where imputation/fallbacks are present, pattern mismatches that are gracefully handled).

---

### Syntax and Implementation Rules
1. **Method Call Syntax**:
   - Every suggestion must start with a dot `.` followed by the method call (e.g., `.isComplete('col')`, `.hasCompleteness('col', lambda x: ...)`).
   - Use only the functions from the Available PyDeequ Functions reference below.
2. **Regex Patterns**:
   - Always use raw strings for regex patterns (e.g., `r"^\d+$"`) to prevent backslash escaping bugs.
3. **SQL Conditions (`satisfies`)**:
   - Enclose column names in backticks (e.g., `.satisfies('`col` IS NULL OR `col` > 0', 'col_positive')`).
4. **Lambda Expressions**:
   - Ensure thresholds in lambdas align realistically with `target_column_desc` and the logic in `code_snippet`.
5. **Assumption Linking**:
   - Every constraint must reference the integer indices (from 0) of the corresponding assumption(s) it tests in `"linked assumptions"`.

### Available PyDeequ Functions

#### Row-Level Functions:
- `.isComplete(column)`: Validates column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness ratio with a lambda `lambda x: ...` (0.0 to 1.0).
- `.areComplete(columns)`: Validates all specified columns have no null values.
- `.haveCompleteness(columns, assertion)`: Validates completeness across a set of columns.
- `.areAnyComplete(columns)`: Validates at least one column in a set has no nulls.
- `.satisfies(columnCondition, constraintName, assertion=None)`: SQL WHERE clause condition on row level.
- `.hasPattern(column, pattern, assertion=None, name=None)`: Regex match on string values.
- `.containsCreditCardNumber(column, assertion=None)`
- `.containsEmail(column, assertion=None)`
- `.containsURL(column, assertion=None)`
- `.containsSocialSecurityNumber(column, assertion=None)`
- `.hasDataType(column, datatype, assertion=None)`: `ConstrainableDataTypes.{Null, Fractional, Integral, Boolean, String, Numeric}`.
- `.isNonNegative(column, assertion=None)`: Validates column >= 0.
- `.isPositive(column, assertion=None)`: Validates column > 0.
- `.isLessThan(columnA, columnB, assertion=None)`: Validates columnA < columnB.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA <= columnB.
- `.isGreaterThan(columnA, columnB, assertion=None)`: Validates columnA > columnB.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA >= columnB.
- `.isContainedIn(column, allowed_values, assertion=None)`: Validates values are in a list/set.

#### Aggregate-Level Functions:
- `.hasSize(assertion)`: Validates total row count (`lambda x: x >= ...`).
- `.haveAnyCompleteness(columns, assertion)`: Validates at least one column meets completeness threshold.
- `.isUnique(column)`: Validates no duplicates exist in the column.
- `.hasUniqueness(columns, assertion)`: Validates uniqueness ratio (values occurring exactly once / total rows).
- `.hasDistinctness(columns, assertion)`: Validates distinct values / total rows.
- `.hasUniqueValueRatio(columns, assertion)`: Validates unique values / distinct values.
- `.hasNumberOfDistinctValues(column, assertion, binningUdf=None, maxBins=1000)`: Validates distinct count.
- `.hasMutualInformation(columnA, columnB, assertion)`
- `.hasApproxQuantile(column, quantile, assertion)`: Quantile check (e.g., 0.5 for median).
- `.hasMinLength(column, assertion)`: Minimum string length.
- `.hasMaxLength(column, assertion)`: Maximum string length.
- `.hasMin(column, assertion)`: Minimum numeric value.
- `.hasMax(column, assertion)`: Maximum numeric value.
- `.hasMean(column, assertion)`: Mean numeric value.
- `.hasStandardDeviation(column, assertion)`: Standard deviation.
- `.hasCorrelation(columnA, columnB, assertion)`: Pearson correlation between two columns.
