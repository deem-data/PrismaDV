### Constraint Level Strategy (`error` vs. `warning`)

**CRITICAL EVALUATION PRINCIPLE**: 
Data quality runners reject corrupted batches **exclusively when `error`-level constraints fail**. Constraints configured as `"warning"` log informational alerts but **never reject a batch**. Therefore:
- **Default to `"error"` for assumption-backed checks**: If an assumption defines allowed values, category memberships, formats, ranges, non-null expectations, or uniqueness, set `level: "error"`.
- **Do NOT demote checks to `"warning"` merely because the Python script contains fallback handling**: Downstream code often uses defensive programming (e.g., `.fillna()`, `errors='coerce'`, dictionary `.get(..., default)`). Data quality verification exists to intercept corrupted data upstream *before* it silently degrades logic or triggers fallback values.
- **Assign `"error"` to**:
  - Categorical domain constraints (e.g., `.isContainedIn(...)`).
  - Completeness and presence checks when data is required or bounded (e.g., `.isComplete(...)`, `.hasCompleteness(...)`).
  - Format, pattern, and data type validity (e.g., `.hasPattern(...)`, `.hasDataType(...)`, `.containsURL(...)`).
  - Value bounds and invariants (e.g., `.isNonNegative(...)`, `.satisfies(...)`, `.isGreaterThan(...)`).
  - Uniqueness and primary key assumptions (e.g., `.isUnique(...)`, `.hasUniqueness(...)`).
- **Assign `"warning"` strictly to**:
  - Non-critical, soft statistical distribution shifts or advisory metrics that do not indicate data corruption.
  - *Mandatory*: At least one constraint in the output must be set to `level: "error"`. Never produce an output containing only `"warning"` constraints.

---

### Calibrating Thresholds and Avoiding Alarms

1. **Prevent False Alarms (Safe Data Rejection)**:
   - Base your assertions on the baseline profile in `target_column_desc`.
   - Leave a reasonable statistical tolerance for natural batch variance. For example:
     - If completeness is ~`0.898`, an overly tight threshold like `lambda x: x >= 0.89` can fail safe batches due to normal variance. A calibrated threshold like `lambda x: x >= 0.75` or `lambda x: x >= 0.80` may prevent false alarms, *provided* content checks are also in place.
     - For `.isContainedIn`, if rare unexpected values can legitimately appear, use an assertion like `lambda x: x >= 0.95` or `lambda x: x >= 0.99`, but keep it at `"error"` level so heavy categorical corruption is still rejected.
2. **Prevent Missed Errors (Corrupted Data Slipping Through)**:
   - A single generic check (e.g., just `.isComplete`) often fails to detect data corruption (e.g., corrupted formats, invalid strings, out-of-domain categories).
   - Test assumptions with complementary constraints where appropriate (e.g., testing both completeness and value validity/format if indicated by the assumptions and code).
   - If an assumption specifies a set of allowed values, ALWAYS check category containment (`.isContainedIn`) at `"error"` level.

### Available PyDeequ Functions Reference

#### Row-Level Functions:
- `.isComplete(column)`: Validates column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness ratio (0.0 to 1.0) with a lambda.
- `.areComplete(columns)`: Validates all specified columns have no null values.
- `.haveCompleteness(columns, assertion)`: Validates completeness across a set of columns.
- `.areAnyComplete(columns)`: Validates at least one column in a set has no nulls.
- `.satisfies(columnCondition, constraintName, assertion=None)`: SQL WHERE clause condition on row level. Column names MUST be enclosed in backticks.
- `.hasPattern(column, pattern, assertion=None, name=None)`: Regex match on string values.
- `.containsCreditCardNumber(column, assertion=None)`
- `.containsEmail(column, assertion=None)`
- `.containsURL(column, assertion=None)`
- `.containsSocialSecurityNumber(column, assertion=None)`
- `.hasDataType(column, datatype, assertion=None)`: `ConstrainableDataTypes.{Null, Fractional, Integral, Boolean, String, Numeric}`.
- `.isNonNegative(column, assertion=None)`: Validates column >= 0.
- `.isPositive(column, assertion=None)`: Validates column > 0.
- `.isLessThan(columnA, columnB, assertion=None)`: Validates columnA < columnB.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA <= columnB.
- `.isGreaterThan(columnA, columnB, assertion=None)`: Validates columnA > columnB.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA >= columnB.
- `.isContainedIn(column, allowed_values, assertion=None)`: Validates values belong to an allowed list/set.

#### Aggregate-Level Functions:
- `.hasSize(assertion)`: Validates total row count (`lambda x: x >= ...`).
- `.haveAnyCompleteness(columns, assertion)`: Validates at least one column meets completeness threshold.
- `.isUnique(column)`: Validates column has no duplicates.
- `.hasUniqueness(columns, assertion)`: Validates uniqueness ratio (unique occurrences / total rows).
- `.hasDistinctness(columns, assertion)`: Validates distinct values / total rows.
- `.hasUniqueValueRatio(columns, assertion)`: Validates unique values / distinct values.
- `.hasNumberOfDistinctValues(column, assertion, binningUdf=None, maxBins=1000)`: Validates distinct count.
- `.hasMutualInformation(columnA, columnB, assertion)`
- `.hasApproxQuantile(column, quantile, assertion)`: Quantile check (e.g., 0.5 for median).
- `.hasMinLength(column, assertion)`: Minimum string length.
- `.hasMaxLength(column, assertion)`: Maximum string length.
- `.hasMin(column, assertion)`: Minimum numeric value.
- `.hasMax(column, assertion)`: Maximum numeric value.
- `.hasMean(column, assertion)`: Mean numeric value.
- `.hasStandardDeviation(column, assertion)`: Standard deviation.
- `.hasCorrelation(columnA, columnB, assertion)`: Pearson correlation between two columns.
