### Critical Severity Level Rules (`error` vs `warning`)

In an automated data validation gate, the severity level determines whether a failing check halts the pipeline (`error`) or allows the batch to proceed while logging an alert (`warning`). 

**The Gatekeeper Principle:**
If a check is marked as `warning`, the validation gate **will not reject corrupted data**. The corrupted data will proceed to downstream pandas/Python execution, where bad values cascade into runtime crashes (`KeyError`, `TypeError`, `ValueError`, `ZeroDivisionError`), empty tables, or silent data corruption—resulting in **False Negatives** in data validation.

#### When to assign `level: "error"` (Default Rule for all Contractual Checks):
Assign **`error`** to any constraint enforcing structural, schema, type, completeness, domain, or value integrity contracts required for correct pipeline execution:
1. **Data Types (`.hasDataType`)**:
   - MUST be marked as **`error`**. 
   - **Crucial**: Do NOT downgrade `.hasDataType` to `warning` simply because downstream pandas code contains defensive coercions like `pd.to_numeric(..., errors='coerce')` or `astype(...)`. When string-polluted or invalid types are coerced to `NaN`, those NaNs cascade into downstream calculations, aggregations, feature pipelines, or output exports that crash or corrupt downstream results.
2. **Column Completeness (`.isComplete`, `.hasCompleteness`)**:
   - MUST be marked as **`error`**.
   - If downstream code assumes full completeness, use `.isComplete` with `level: "error"`.
   - If an assumption defines a completeness ratio threshold (e.g., completeness >= 0.95), violation of this threshold breaks the schema contract and MUST be marked as **`error`**. Do not downgrade threshold completeness checks to `warning`.
3. **Value Range and Domain Integrity (`.isNonNegative`, `.isPositive`, `.satisfies`)**:
   - MUST be marked as **`error`**.
   - Violations (such as negative values, zero in denominators, or out-of-bound quantities) violate business logic and cause arithmetic, log, or division-by-zero errors.
4. **Allowed Categorical Values (`.isContainedIn`)**:
   - MUST be marked as **`error`**.
   - Unhandled categorical values cause unmapped keys in dictionary lookups (`.map()`), filtering drops, empty subsets, or logic branch failures.
5. **Key Uniqueness (`.isUnique`, `.hasUniqueness`)**:
   - MUST be marked as **`error`**.
   - Primary keys, index columns, or merge keys must maintain uniqueness contracts to prevent join Cartesian explosions.

#### When to assign `level: "warning"` (Strictly Restricted):
Assign **`warning`** ONLY for soft statistical quality metrics or distribution monitoring where values are structurally and typographically valid, and a deviation does not crash or invalidate the pipeline:
1. Statistical drift checks on distributions: `.hasMean`, `.hasStandardDeviation`, `.hasApproxQuantile`, `.hasCorrelation`.
2. Informational cardinality or distinct value count metrics where variations do not affect join integrity or business logic.

### Available PyDeequ Functions Reference

#### Row-Level Functions:
- `.isComplete(column)`: Validates that a column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness fraction (0.0 to 1.0) meets a lambda assertion (e.g., `lambda x: x >= 0.95`).
- `.areComplete(columns)`: Validates that all columns in a list contain no null values.
- `.haveCompleteness(columns, assertion)`: Validates completeness fraction across a set of columns.
- `.areAnyComplete(columns)`: Validates that at least one column in a set is complete.
- `.satisfies(columnCondition, constraintName, assertion=None)`: Validates a custom SQL WHERE clause condition. Example: `.satisfies('`col1` <= `col2`', 'col1_le_col2')`.
- `.hasPattern(column, pattern, assertion=None, name=None)`: Validates regex pattern match. Use raw strings (`r"..."`).
- `.hasDataType(column, datatype, assertion=None)`: Validates values conform to `ConstrainableDataTypes` enum.
- `.isContainedIn(column, allowed_values, assertion=None)`: Validates non-null values are within a specified list.
- `.isNonNegative(column, assertion=None)`: Validates values are >= 0.
- `.isPositive(column, assertion=None)`: Validates values are > 0.
- `.isLessThan(columnA, columnB, assertion=None)`: Validates columnA < columnB row-wise.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA <= columnB row-wise.
- `.isGreaterThan(columnA, columnB, assertion=None)`: Validates columnA > columnB row-wise.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA >= columnB row-wise.
- `.containsEmail(column, assertion=None)`: Validates email address format.
- `.containsURL(column, assertion=None)`: Validates URL format.
- `.containsCreditCardNumber(column, assertion=None)`: Validates credit card number format.
- `.containsSocialSecurityNumber(column, assertion=None)`: Validates US SSN format.

#### Aggregate-Level Functions:
- `.hasSize(assertion)`: Validates total row count via lambda assertion (e.g., `lambda x: x >= 100`).
- `.isUnique(column)`: Validates that every value in the column is distinct.
- `.hasUniqueness(columns, assertion)`: Validates uniqueness fraction (0.0 to 1.0) via lambda assertion.
- `.hasDistinctness(columns, assertion)`: Validates distinct values count / total rows fraction.
- `.hasUniqueValueRatio(columns, assertion)`: Validates ratio of unique values to distinct values.
- `.hasNumberOfDistinctValues(column, assertion, binningUdf=None, maxBins=1000)`: Validates count of distinct values.
- `.hasMin(column, assertion)`: Validates minimum value.
- `.hasMax(column, assertion)`: Validates maximum value.
- `.hasMean(column, assertion)`: Validates mean value.
- `.hasStandardDeviation(column, assertion)`: Validates standard deviation.
- `.hasApproxQuantile(column, quantile, assertion)`: Validates quantile value.
- `.hasMinLength(column, assertion)`: Validates minimum string length.
- `.hasMaxLength(column, assertion)`: Validates maximum string length.
- `.hasCorrelation(columnA, columnB, assertion)`: Validates Pearson correlation (-1.0 to 1.0).
- `.hasMutualInformation(columnA, columnB, assertion)`: Validates mutual information.
