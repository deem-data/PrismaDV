### Severity Level Assignment Rules (`error` vs `warning`)

In PyDeequ validation gates, the severity level determines whether a failing check halts the pipeline (`error`) or merely emits a log (`warning`). If a check is marked as `warning`, corrupted data will pass through the gate and crash downstream operations or corrupt analytical outputs, resulting in critical validation False Negatives.

#### When to assign **`level: "error"`** (Standard Default):
Assign `level: "error"` to any check that validates core data integrity, schema contracts, or domain validity:
1. **Column Completeness (`.isComplete`)**:
   - The column is assumed to have no missing values, is required by downstream logic, is used in groupbys/joins/indexing, or is selected in downstream output files.
2. **Data Types (`.hasDataType`)**:
   - The column is assumed to be Integral, Fractional, Numeric, String, or Boolean.
   - **Crucial**: Do NOT set `warning` merely because pandas uses `pd.to_numeric(..., errors='coerce')` or defensive casting. `errors='coerce'` converts corrupted values to NaNs, which silences errors while corrupting calculations and downstream metrics. Data type constraints must be set to `error`.
3. **Allowed Categorical Values (`.isContainedIn`)**:
   - The column assumes a closed set of categories (e.g., status strings, tiers, department names).
   - **Crucial**: Do NOT set `warning` merely because pandas handles categories with `.groupby()` or `.map().fillna()`. Unhandled categories distort aggregations, drop rows, or corrupt business rules. These must be set to `error`.
4. **Value Domain & Range (`.isNonNegative`, `.isPositive`, `.satisfies`)**:
   - The column assumes non-negativity (e.g., tenure, age, counts, wages >= 0), positivity (> 0), or domain limits (e.g., percentages, ratios).
   - **Crucial**: Do NOT set `warning` because the code has `.clip()` or `.fillna()`. Negative tenure, negative salaries, or out-of-bound ratios represent corrupted records and must be rejected with `error`.
5. **Key Uniqueness (`.isUnique`)**:
   - The column represents a primary key, employee ID, unique record identifier, or unique index.

#### When to assign **`level: "warning"`** (Strictly Limited):
Assign `level: "warning"` ONLY for soft statistical drift or advisory thresholds:
1. **Statistical Drift / Distribution Metrics**:
   - Aggregate metrics such as `.hasMean()`, `.hasStandardDeviation()`, or quantile boundaries (`.hasApproxQuantile()`).
2. **Soft Completeness Margins**:
   - Completeness assertions that explicitly tolerate missing values up to a threshold (e.g., `.hasCompleteness('col', lambda x: x >= 0.95)` when downstream logic is explicitly designed to handle up to 5% nulls).
3. **Soft Size Thresholds**:
   - Row count checks like `.hasSize(lambda x: x >= 100)` where lower volume is undesirable but not invalid.

### PyDeequ Reference

#### Row-Level Constraints:
- `.isComplete(column)`: Validates that a column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness ratio (0.0 to 1.0) meets a lambda assertion (e.g., `lambda x: x >= 0.95`).
- `.areComplete(columns)`: Validates that all columns in a list contain no null values.
- `.hasDataType(column, datatype, assertion=None)`: Validates data type against `ConstrainableDataTypes`.
- `.isContainedIn(column, allowed_values, assertion=None)`: Validates non-null values are within an allowed list.
- `.isNonNegative(column, assertion=None)`: Validates values are >= 0.
- `.isPositive(column, assertion=None)`: Validates values are > 0.
- `.satisfies(columnCondition, constraintName, assertion=None)`: Custom SQL WHERE clause (e.g., ``.satisfies('`col1` <= `col2`', 'col1_le_col2')``).
- `.isLessThan(columnA, columnB, assertion=None)`: Validates columnA < columnB row-wise.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA <= columnB row-wise.
- `.isGreaterThan(columnA, columnB, assertion=None)`: Validates columnA > columnB row-wise.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: Validates columnA >= columnB row-wise.
- `.hasPattern(column, pattern, assertion=None, name=None)`: Regex match using raw string literal (e.g., `r"^\d{4}-\d{2}-\d{3}$"`).

#### Aggregate & Statistical Constraints:
- `.isUnique(column)`: Validates that every value in the column is distinct (100% unique).
- `.hasSize(assertion)`: Validates total row count via lambda assertion (e.g., `lambda x: x >= 100`).
- `.hasNumberOfDistinctValues(column, assertion)`: Validates count of distinct values.
- `.hasMin(column, assertion)`: Validates minimum value.
- `.hasMax(column, assertion)`: Validates maximum value.
- `.hasMean(column, assertion)`: Validates mean value.
- `.hasStandardDeviation(column, assertion)`: Validates standard deviation.
- `.hasApproxQuantile(column, quantile, assertion)`: Validates quantile value.
