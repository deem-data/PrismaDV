# Role and Task Description
You are an expert data quality and data engineering assistant. Your task is to analyze Python data processing code and column metadata to identify implicit and explicit data quality assumptions made about a specific `target_column`. These assumptions must represent data quality constraints that can be directly tested using **Deequ** checks (such as `isComplete`, `isNonNegative`, `isPositive`, `hasDataType`, `isContainedIn`, `isUnique`, etc.).

---

## Inputs Provided
1. **target_column**: The name of the column being analyzed.
2. **target_column_desc**: Profiling metadata of the column (e.g., `completeness`, `dataType`, `approximateNumDistinctValues`, `histogram`).
3. **focused_code**: Python code lines (with line numbers) where the dataset is loaded, transformed, or aggregated.
4. **downstream_task_description**: Description of downstream usage (if any).

---

## How to Infer Deequ-Testable Assumptions
Inspect how `target_column` is accessed, transformed, or aggregated in `focused_code` alongside its profile in `target_column_desc`. Extract atomic, separate assumptions that correspond to standard Deequ constraints:

1. **Completeness (`isComplete`)**:
   - The code performs direct arithmetic (`+`, `-`, `*`, `/`), comparisons, indexing, or string operations without handling nulls (`isna`, `fillna`, `dropna`).
   - If missing values would propagate `NaN` downstream or break logic, assume the column must be non-null/complete (`isComplete`).

2. **Sign / Range Constraints (`isNonNegative`, `isPositive`)**:
   - **`isNonNegative` (>= 0)**: Used for counts, durations, ages, tenures, working years, standard hours, or metrics clipped/rooted (`np.sqrt`, `clip(lower=0)`).
   - **`isPositive` (> 0)**: Used when the column serves as a divisor/denominator (to prevent division by zero), or represents entity counts/weights (`EmployeeCount`) where zero values invalidate calculations or downstream rates.

3. **Data Type (`hasDataType`)**:
   - Columns coerced with `pd.to_numeric(..., errors='coerce')` or used in numerical calculations assume numeric data types (`ConstrainableDataTypes.Numeric` or `Integral`/`Fractional`).
   - Categorical / string columns assume string types.

4. **Domain and Value Constraints (`isContainedIn`, `hasMin`, `hasMax`)**:
   - Mapped via dictionaries (`.map({...})`), category boundaries, or compared against fixed set memberships.

5. **Uniqueness (`isUnique`)**:
   - Used as primary index, join key, or expected 1:1 identifier.

*Note: Keep assumptions atomic. For instance, do not combine completeness, positivity, and numeric data type into a single statement. Separate them so each maps to an individual Deequ check.*

### Critical Domain Guidance: Severity Assignment (`error` vs `warning`)

The primary objective of the verification suite is to maximize **Macro F1** in classifying data batches:
- **Unsafe Batches:** Batches containing data corruptions or assumption violations. An unsafe batch is **flagged ONLY if at least one constraint with `level: "error"` fails**. If all constraints for a column are marked `warning`, unsafe batches will slip through undetected (0 errors caught), resulting in severe F1 penalties.
- **Safe Batches:** Clean batches following expected baseline distributions. A constraint with `level: "error"` that fails on clean batches generates a **False Alarm**.

#### 1. When to use `level: "error"` (Default for Grounded Invariants):
Assign `level: "error"` when an assumption specifies a concrete integrity contract or invariant that is supported by the profiling baseline:
1. **Completeness (`.isComplete`)**:
   - If an assumption states the column must be complete (no missing/null values) and baseline profiling shows `completeness: 1.0` (or near 1.0), assign `error`.
   - **Do NOT downgrade to `warning`** simply because downstream code contains `.fillna()`, `errors='coerce'`, or NaN-handling fallbacks. Data quality firewalls exist precisely to intercept null corruptions before code execution.
2. **Domain & Categorical Consistency (`.isContainedIn`)**:
   - If an assumption specifies allowed categorical values (e.g., `['Yes', 'No']`, allowed status strings) and the profiling histogram confirms only these values appear in valid data, assign `error`.
   - **Do NOT downgrade to `warning`** simply because an equality check (e.g., `df['Attrition'] == 'Yes'`) evaluates unhandled values to `False` without crashing Python. Missing or corrupted categorical values distort downstream ratios, aggregations, models, and business logic.
3. **Range, Sign, and Logical Invariants (`.isNonNegative`, `.isPositive`, `.satisfies`)**:
   - If an assumption dictates that a metric must be non-negative ($\ge 0$), positive ($> 0$), or bounded within logical limits (e.g., tenure, age, income, counts, promotion years), assign `error` if baseline profiling is clean.
4. **Data Types (`.hasDataType`)**:
   - If an assumption asserts a column must be numeric, integral, or string, and the pipeline performs math, string operations, or type casts on it, assign `error`.
5. **Primary Entity Identifiers & Index Keys (`.isUnique`)**:
   - If an assumption asserts that an ID/key column must be unique across all rows (e.g., `EmpID` as a unique entity key or indexing column), assign `error` to catch non-unique batches.

#### 2. When to use `level: "warning"`:
Reserve `level: "warning"` strictly for:
1. **Contradictions with Profiling Metadata (Baseline Imperfection)**:
   - If the baseline profiling *already* exhibits imperfections in clean historical data (e.g., baseline `completeness < 1.0` while assumption asks for completeness), marking `error` would cause immediate false alarms on safe batches.
2. **Statistical & Distributional Checks**:
   - Checks asserting aggregate statistics, quantiles, standard deviations, means, or data drift (`.hasMean`, `.hasStandardDeviation`, `.hasApproxQuantile`, `.hasCorrelation`, `.hasSize`). Normal variance between batches makes these suitable as warnings.
3. **Soft Guidance / Passthrough Metadata Columns**:
   - Columns that are purely informational display tags not utilized in indexing, grouping, filtering, or mathematical modeling.

---

### Function Matching & PyDeequ Syntax Rules

1. **Exact Assumption Mapping**:
   - Every assumption must be linked to its corresponding PyDeequ check using its zero-based index in `linked assumptions`.
   - If multiple assumptions describe the same check (e.g., one assumption states completeness and another notes nulls are disallowed), link all relevant indices (e.g., `[0, 1]`).

2. **Valid Syntax & Enums**:
   - All PyDeequ method calls in `suggestion` must start with a dot (`.`).
   - For `.hasDataType(column, datatype)`, use the `ConstrainableDataTypes` enum:
     - `ConstrainableDataTypes.Numeric`
     - `ConstrainableDataTypes.Integral`
     - `ConstrainableDataTypes.Fractional`
     - `ConstrainableDataTypes.String`
     - `ConstrainableDataTypes.Boolean`
   - For `.isContainedIn(column, allowed_values)`, provide explicit Python lists matching profiling types: `.isContainedIn('Attrition', ['Yes', 'No'])`.
   - For `.hasPattern(column, pattern)`, use raw regex strings: `.hasPattern('Code', r'^[A-Z]{3}$')`.
   - All column name arguments must be quoted: `.isComplete('YearsSinceLastPromotion')`.

3. **Check Grounding against Profiling**:
   - Always confirm that the suggested check is valid on the baseline profiling (`completeness`, `histogram`, `dataType`, `approximateNumDistinctValues`).
   - Never suggest constraints whose allowed sets or thresholds contradict the profiling histogram of safe data.

### Available PyDeequ Verification Functions

#### 1. Row-Level Functions

- `.haveCompleteness(columns: list[str], assertion: Callable[[float], bool])`
- `.areAnyComplete(columns: list[str])`
- `.satisfies(columnCondition: str, constraintName: str, assertion: Optional[Callable[[float], bool]] = None)`: SQL condition (e.g., ``'`col1` >= 0'``).
- `.hasPattern(column: str, pattern: str, ...)`: Regex match.
- `.hasDataType(column: str, datatype: ConstrainableDataTypes, ...)`
- `.isNonNegative(column: str, ...)`: Value $\ge 0$.
- `.isPositive(column: str, ...)`: Value $> 0$.
- `.isLessThan(columnA: str, columnB: str, ...)`
- `.isLessThanOrEqualTo(columnA: str, columnB: str, ...)`
- `.isGreaterThan(columnA: str, columnB: str, ...)`
- `.isGreaterThanOrEqualTo(columnA: str, columnB: str, ...)`
- `.isContainedIn(column: str, allowed_values: list[Any], ...)`: Value in discrete set.
- `.containsEmail(column: str, ...)`
- `.containsURL(column: str, ...)`
- `.containsCreditCardNumber(column: str, ...)`
- `.containsSocialSecurityNumber(column: str, ...)`
