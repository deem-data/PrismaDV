### Task Description & Objectives

You will be provided with:
1. `target_column`: The column being evaluated.

### Key Guidelines for Translating Assumptions to PyDeequ Checks

#### 1. Assigning Severity Levels (`"error"` vs `"warning"`):
- **`"error"`**:
  - The script will **crash at runtime** if the assumption is violated.
  - Examples:
    - Missing columns or unexpected NaNs passed into unhandled operations (e.g., strict `.astype(float)`, unhandled `.map(dict)` without defaults, non-coerced type conversions).
    - Unhandled `ZeroDivisionError` (e.g., dividing by an unhandled zero/null denominator).
    - Columns strictly required to exist and be non-null when included in mandatory downstream outputs or index settings (`df.set_index('col')`).
- **`"warning"`**:
  - The script handles anomalies gracefully via defensive coding, but quality or semantics are degraded.
  - Examples:
    - Defensive conversion: `pd.to_numeric(..., errors='coerce')` or `.fillna(...)` or `.replace(...)`.
    - Imputation masks bad data: e.g., `df['col'].fillna(0)` prevents a crash, but invalid types or excessive nulls lead to skewed calculations or loss of information.
    - Out-of-bounds semantic values (e.g., negative tenure, negative age) that propagate without throwing exceptions.

#### 2. Selecting Appropriate & Precise Constraints:

- **Data Types (`hasDataType`)**:
  - Match the exact type indicated in `target_column_desc`:
    - Integer / discrete count / age / ID: `ConstrainableDataTypes.Integral`
    - Float / continuous / monetary amounts / ratios: `ConstrainableDataTypes.Fractional`
    - Categorical / strings: `ConstrainableDataTypes.String`
    - Boolean flags: `ConstrainableDataTypes.Boolean`
  - *Handling Nulls with `hasDataType`*:
    - If `target_column_desc['completeness'] < 1.0` or missing values are expected, `hasDataType` must include a threshold assertion (e.g., `lambda x: x >= 0.95` or matching the completeness fraction) so nulls do not cause false assertion failures.

- **Completeness (`isComplete` vs `hasCompleteness`)**:
  - If `completeness == 1.0` and downstream code does not impute nulls (or assumes full presence), use `.isComplete(column)`.
  - If missing values are tolerated/imputed (completeness < 1.0) but bounded, validate completeness using `.hasCompleteness(column, lambda x: x >= threshold)`.

- **Domain Semantics & Positivity / Non-Negativity**:
  - Always validate semantic validity beyond basic type casting:
    - Tenures, years with company/manager, promotions, distances, incomes: Use `.isNonNegative(column)` (values $\ge 0$).
    - Ages, headcounts, denominators used in division: Use `.isPositive(column)` (values $> 0$) to avoid division by zero or nonsensical zero/negative entities.
    - Constant flags or fixed domain counts (e.g., `EmployeeCount == 1`): If profiling indicates a single distinct value or strict constant domain, consider `.isPositive(...)`, `.hasMin(...)`, or `.isContainedIn(...)`.

- **Categoricals & Allowed Values**:
  - For categorical codes, status fields, or bins, validate the exact set using `.isContainedIn(column, allowed_values)`.

- **Cross-Column Relationships**:
  - For interrelated metrics (e.g., `YearsWithCurrManager <= YearsAtCompany`), use `.isLessThanOrEqualTo('colA', 'colB')` or `.satisfies('`colA` <= `colB`', 'colA_le_colB')`.

---

### Available PyDeequ Functions

#### Row-Level Functions:
- `.isComplete(column)`: Column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness fraction (0.0 to 1.0).
- `.areComplete(columns)`: All columns in the list are complete.
- `.haveCompleteness(columns, assertion)`: Completeness fraction across column set.
- `.satisfies(columnCondition, constraintName, assertion=None)`: Custom SQL WHERE clause. Columns must be backtick-escaped (e.g., `` `col1` <= `col2` ``).
- `.hasPattern(column, pattern, assertion=None, name=None)`: Regex pattern check.
- `.hasDataType(column, datatype, assertion=None)`: Validates type using `ConstrainableDataTypes.{Integral, Fractional, String, Boolean, Numeric, Null}`.
- `.isNonNegative(column, assertion=None)`: Numeric values are $\ge 0$.
- `.isPositive(column, assertion=None)`: Numeric values are $> 0$.
- `.isLessThan(columnA, columnB, assertion=None)`: `columnA < columnB`.
- `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`: `columnA <= columnB`.
- `.isGreaterThan(columnA, columnB, assertion=None)`: `columnA > columnB`.
- `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`: `columnA >= columnB`.
- `.isContainedIn(column, allowed_values, assertion=None)`: Values exist within allowed list.

#### Aggregate-Level Functions:
- `.hasSize(assertion)`: Validates total dataset row count.
- `.isUnique(column)`: Values are strictly unique (no duplicates).
- `.hasUniqueness(columns, assertion)`: Fraction of unique values.
- `.hasDistinctness(columns, assertion)`: Distinct values / total rows.
- `.hasNumberOfDistinctValues(column, assertion)`: Absolute distinct count.
- `.hasMin(column, assertion)`: Minimum numeric value.
- `.hasMax(column, assertion)`: Maximum numeric value.
- `.hasMean(column, assertion)`: Average numeric value.
- `.hasStandardDeviation(column, assertion)`: Standard deviation.
- `.hasApproxQuantile(column, quantile, assertion)`: Quantile value.
- `.hasMinLength(column, assertion)`: Minimum string length.
- `.hasMaxLength(column, assertion)`: Maximum string length.
