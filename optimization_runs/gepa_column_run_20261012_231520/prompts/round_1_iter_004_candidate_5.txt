### Context & Objective
Your goal is to validate input data quality against assumptions derived from downstream code. The validation pipeline evaluates whether "unsafe" batches (data batches containing corrupt, missing, or invalid values that violate assumptions or break code) are correctly detected and flagged.

### Critical Level Guidelines ("error" vs "warning")
- **"error"**: Must be assigned to any check validating a fundamental requirement. If data violating this check would cause runtime exceptions (e.g., `KeyError` from missing column, `ValueError` from failed type conversion, negative inputs into domain formulas) or fundamentally invalidates downstream computations:
  - Column presence and completeness (e.g., `.isComplete('col')`) must be set to **"error"**.
  - Type conformance (e.g., `.hasDataType('col', ConstrainableDataTypes...)`) when code explicitly casts or relies on numeric/integral operations must be set to **"error"**.

  - **Caution**: If you mark critical checks as `"warning"`, unsafe batches will not be caught as errors, causing 0% detection rates on corrupted batches. Do NOT default to `"warning"` merely because pandas/numpy might silently propagate NaNs or negative numbers.
- **"warning"**: Reserve for soft expectations, non-breaking statistical distribution shifts, or non-fatal quality thresholds where downstream code handles degradation gracefully without breaking data contracts.

### Constraint Selection Strategy
1. **Never rely on `hasDataType` alone**:
   - In PyDeequ/Spark, `hasDataType` checks type conformance across non-null values. It does NOT guarantee that the column is non-null. Always pair type checks with `.isComplete(column)` if nulls are prohibited.
2. **Always enforce domain constraints**:
   - For count or volume fields (e.g., enrolled units, credited units, evaluations, approved units, ages), always enforce `.isNonNegative(column)` or `.satisfies('`col` >= 0', 'col_non_negative')`.
   - For bounded metrics (e.g., grades on a 0-20 scale, probabilities on 0-1), enforce range conditions using `.satisfies('`col` >= min_val AND `col` <= max_val', 'name')`.

### Available Functions Reference

#### Row-Level Functions:
- `.isComplete(column)`: Validates column contains no null values.
- `.hasCompleteness(column, assertion)`: Validates completeness fraction (0.0 to 1.0) matches lambda. Example: `.hasCompleteness('credits', lambda x: x >= 0.95)`
- `.areComplete(columns)`: Validates all columns in list contain no null values.

- `.areAnyComplete(columns)`: At least one column in set is complete.
- `.satisfies(columnCondition, constraintName, assertion=None)`: SQL WHERE-clause condition. Use backticks for columns with spaces/special characters. Example: `.satisfies('`grade` >= 0.0 AND `grade` <= 20.0', 'grade_bounds')`
- `.hasPattern(column, pattern, assertion=None, name=None)`: Validates regex pattern. Use raw strings `r"..."`.
- `.hasDataType(column, datatype, assertion=None)`: Validates datatype against `ConstrainableDataTypes.<Type>` where Type is `Integral`, `Fractional`, `Numeric`, `String`, `Boolean`, or `Null`.
- `.isNonNegative(column, assertion=None)`: Validates numeric column values >= 0.
- `.isPositive(column, assertion=None)`: Validates numeric column values > 0.
- `.isLessThan(columnA, columnB, assertion=None)` / `.isLessThanOrEqualTo(columnA, columnB, assertion=None)`
- `.isGreaterThan(columnA, columnB, assertion=None)` / `.isGreaterThanOrEqualTo(columnA, columnB, assertion=None)`
