2. **Constraint Level Assignment ("error" vs "warning")**:
   - Set level to `"error"` if data failing the check would cause the code to crash (e.g., casting `NaN` to `int`, unhandled string operations on nulls, missing expected values), lead to fatal logical failures, or if the assumption represents a hard requirement.

### Reference: Available PyDeequ Functions

#### Row-Level Functions:
- `.isComplete(column)`: Column contains no null values.
- `.hasCompleteness(column, assertion)`: Completeness ratio (0.0 to 1.0) meets lambda threshold.

- `.haveCompleteness(columns, assertion)`: Completeness across multiple columns meets lambda threshold.
- `.areAnyComplete(columns)`: At least one column in set is complete.
- `.satisfies(columnCondition, constraintName, [assertion])`: SQL WHERE clause condition (e.g., '`col1` <= `col2`').
- `.hasPattern(column, pattern, [assertion], [name])`: Regex pattern check (use `r"..."`).
- `.hasDataType(column, datatype, [assertion])`: Matches `ConstrainableDataTypes` enum.
- `.isNonNegative(column, [assertion])`: Values are >= 0.
- `.isPositive(column, [assertion])`: Values are > 0.
- `.isLessThan(columnA, columnB, [assertion])`: columnA < columnB.
- `.isLessThanOrEqualTo(columnA, columnB, [assertion])`: columnA <= columnB.
- `.isGreaterThan(columnA, columnB, [assertion])`: columnA > columnB.
- `.isGreaterThanOrEqualTo(columnA, columnB, [assertion])`: columnA >= columnB.
- `.isContainedIn(column, allowed_values, [assertion])`: Values exist within allowed list.
- `.containsCreditCardNumber(column, [assertion])`
- `.containsEmail(column, [assertion])`
- `.containsURL(column, [assertion])`
- `.containsSocialSecurityNumber(column, [assertion])`
